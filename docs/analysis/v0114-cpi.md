# V0114 CPI changes and instruction-state effects

The instruction checks below were performed on 2026-10-27 for the 1,000 CPI,
4 ms profile. They explain the configuration-write replacement and its PSW
effect. The [sensor map and available settings](../firmware.md#sensor-resolution-cpi)
also describe the other CPI profiles. The counts below refer to the original
1,000 CPI checks, not a hardware validation of every setting. Actual sensor
variant and effective CPI remain unconfirmed.

## Byte change and scope

Baseline sleep-fix, stock-CPI, 4 ms image SHA-256:
`4169e8eec62913ff43bb8693b1144893575fbf9d93ecbbdc3e1b2716ce007028`.

Independently constructed trial SHA-256:
`dc0614392fe61dd049fbf57e5144c2c9670ba1e8f0a03c92a8a7cb584ea00d91`.

- `0x2252`: `01 -> 02`, making the ID31 branch's instruction `7f 02`.
- `[0x2260,0x2262)`: `e4 ff -> 7f 02`, replacing `CLR A; MOV R7,A` with
  `MOV R7,#02` in the ID30 branch.
- Both accepted IDs now transmit `86 02` for normal configuration; the sensor
  reset `86 80` and sleep write `85 b0` are unchanged.
- The three changed bytes are all in page `0x2200`. The polling descriptor,
  sleep trampoline, loader, metadata, clocks, and timers are identical to the
  baseline. No instruction or branch target shifts.

Transmitter `0x2845` clears A at `0x284a` and reads R7 at `0x284e`. Thus removing
the caller's `CLR A` does not alter the transmitted byte or introduce an ACC
dependency. The raw replacement and the unchanged hook jump were independently
decoded with radare2.

## Overflow flag difference

An initial exact-SFR comparison detected one difference for ID31: PSW bit 2
(OV) becomes clear instead of set. The transmitter repeatedly doubles the data
byte with ADD. Its final ADD's OV depends on the final transmitted data bit;
configuration `01` and `02` consequently leave different OV values. The sleep
trampoline preserves that configuration-transmit PSW around its added writes.

This is an expected consequence of changing data, not an effect of removing
the caller's CLR A. Do not claim complete PSW equality against stock CPI.

The original application [control-flow traversal](v0114-integrity-software.md#control-flow-bound)
has only one OV condition:
`0x1550: 20 d2 1c` (`JB OV,0x156f`), immediately after `0x154f: 84` (`DIV AB`).
DIV defines OV. The helper is entered at `0x154a`; no direct jump/call enters
at `0x1550`. The previously resolved computed-dispatch tables do not enter
that helper tail. Other PSW accesses use bit 5 or interrupt save/reset/restore.
The new CPI edits introduce no PSW readers, and the unchanged sleep trampoline
only saves/restores it. Therefore the returned OV difference has no identified
behavioral consumer in these paths. Interrupt handlers save PSW then clear it
for their bodies.

With this explicitly checked exception, live RAM, all other SFR/PSW bits,
stack balance and peak stack use match the existing 4 ms sleep candidate.
ID30's return state is identical; rejected IDs are unchanged.

## Executed probes

- All 256 possible initialization ID bytes: only `30/31` reach the new
  configuration and sleep writes; other IDs retain the rejection behavior.
- 2,560 accepted-branch comparisons: both IDs, all 256 starting PSW values,
  five stack positions, randomized RAM/SFR contents. Exact outgoing bytes and
  resulting CPU state checked, allowing only the documented ID31 OV difference.
- Configuration-gated polling, rejected ID and 177-call retry path, then the
  actual post-wake reset tail and 65-call retry path. CPI and sleep writes are
  reapplied on each successful reinitialization.
- 816 instruction-boundary injections of the actual quiet USB ISR across both
  accepted branches; emitted bytes and final live state match uninterrupted
  execution.

The model executes actual TX/RX and initializer instructions. Delay and other
input-service routines are stubbed; sensor ID bits are supplied. These checks
do not model optical resolution, hardware clock timing, USB scheduling, or
the physical sensor's interpretation of configuration register `0x06`.
